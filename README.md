# Ashen Realms — 2D MMORPG в Telegram

Мультиплеерная 2D MMORPG, работающая как Telegram Mini App. Авторитетный сервер,
предсказание движения на клиенте, монстры с ИИ, зоны разной сложности, прогресс в Postgres.

Весь стек — TypeScript: одни и те же модели, формулы боя и коллизии используются
и клиентом, и сервером из `packages/shared`.

## Что уже работает

- **Вход через Telegram** — `initData` проверяется по HMAC-подписи на сервере, в обмен выдаётся JWT.
- **Реалтайм-мир** — Colyseus, серверный тик 15 Гц, до 100 игроков в комнате.
- **Движение** — виртуальный джойстик и WASD, предсказание на клиенте с реконсиляцией по `lastSeq`.
- **Бой** — базовая атака конусом, 4 умения на класс (урон по дуге, нова, рывок, щит), криты, числа урона.
- **3 класса** — Маг, Следопыт, Рыцарь смерти: свои характеристики, скорость, дальность и умения.
- **92 монстра в 10 зонах** — ИИ с аггро, преследованием, поводком, возвратом домой и респауном.
- **Прогрессия** — опыт, уровни до 40, пересчёт характеристик, сохранение в Postgres.
- **Безопасная площадь** — в радиусе 300 px от точки возрождения монстры не агрятся и не заходят.
- **Чат**, шкалы HP/MP/опыта, экран смерти, гаптика Telegram.

## Стек

| Слой | Что используем |
| --- | --- |
| Клиент | TypeScript, **Phaser 3.90** (рендер, тайлмапы, анимации), **React 19** + **Tailwind 4** (HUD), **Vite 8** |
| Реалтайм | **Colyseus 0.16** — комнаты, бинарная дельта-синхронизация состояния |
| HTTP | **Express 5**, JWT, проверка Telegram `initData`, раздача собранного клиента |
| Данные | **PostgreSQL 17** + **Drizzle ORM** |
| Бот | **grammY**, long polling в том же процессе |
| Общий код | `packages/shared` — константы, математика, карта, классы, монстры, формулы урона, схемы сообщений (Zod) |
| Инфра | pnpm workspaces, Docker Compose (Postgres) |

Всё серверное — **один процесс на одном порту**: статика, API, игровой
WebSocket и бот. Клиент и API оказываются на одном домене, поэтому нет ни CORS,
ни адресов, которые надо прописывать, ни второго секрета, который может
разойтись с первым. Разделить обратно на сервисы можно переменными
`SERVE_CLIENT` и `RUN_BOT` — см. [`docs/deploy-railway.md`](docs/deploy-railway.md).

### Почему такие версии

`colyseus` намеренно зафиксирован на **0.16.x**: клиент `colyseus.js@0.16` работает
с `@colyseus/schema@3`, а серверные ветки 0.17 и 0.18 требуют schema 4 и 5 — они
между собой несовместимы по формату сериализации. Также `@colyseus/core` закреплён
на `0.16.24` через `pnpm.overrides`: в 0.16.25 опубликован битый манифест
(`"@colyseus/greeting-banner": "workspace:^"`), из-за которого установка падает.

Phaser взят из ветки 3.x, а не 4.x — ради стабильного API и большого корпуса
документации и туториалов. Переход на Phaser 4 позже почти не затрагивает игровой код.

## Быстрый старт

```bash
pnpm install
cp apps/server/.env.example apps/server/.env
cp apps/client/.env.example apps/client/.env

pnpm dev:server               # игра + API + бот  :2567
pnpm dev:client               # Vite с hot reload :5173
```

Открой `http://localhost:5173`. Вне Telegram работает dev-вход: клиент
отправляет токен `dev:<имя>`, а сервер принимает его, пока `DEV_LOGIN=1`.
**В продакшене `DEV_LOGIN` должен быть `0`.**

Разрешён ли dev-вход, решает сервер: клиент спрашивает об этом
`/api/health` и не предлагает то, что сервер всё равно отклонит.

Хочешь один процесс и локально (как в продакшене) — собери клиент и открой
`http://localhost:2567`:

```bash
pnpm build && pnpm start
```

База не обязательна: без `DATABASE_URL` сервер работает в памяти. Нужен
прогресс — подними Postgres, схему сервер накатит сам при старте:

```bash
docker compose up -d
```

### Запуск внутри Telegram

1. Создай бота у [@BotFather](https://t.me/botfather), положи токен в `BOT_TOKEN`.
2. Собери клиент: `pnpm build` — сервер раздаёт его сам.
3. Подними HTTPS-туннель: `cloudflared tunnel --url http://localhost:2567`
   (или ngrok). Telegram не открывает Mini App по http.
4. Пропиши полученный адрес в `WEBAPP_URL` и запусти `pnpm start`.
5. В боте нажми `/start` → «Играть».

## Спрайты

Арт лежит в `apps/client/public/assets/sprites`:

- `heroes/<класс>/<направление>-<действие>.png` — лист в один ряд, 15 кадров 128×128.
  Восемь направлений (`down`, `down-right`, `right`, …) × `idle` / `run` / `attack`, плюс `die.png`.
- `monsters/<вид>/<действие>.png` — сетка 4 строки = 4 направления (`down`, `up`, `left`, `right`),
  число колонок зависит от анимации.
- `skills/<иконка>.png` — иконки умений 128×128.

`pnpm assets` пересобирает `assets/manifest.json` (размеры кадров и их количество
вычисляются прямо из PNG) и генерирует `packages/shared/src/generated/sprite-ids.ts`.
Добавил новую папку с монстром — просто перезапусти команду.

Точка «ног» спрайта определяется в рантайме по альфа-каналу первого кадра
(`measureAnchor`), поэтому арт с другими отступами встаёт на землю без ручной подгонки.

Земля пока рисуется процедурно (в наборе нет тайлсета) — за это отвечает
`apps/client/src/game/world/terrain.ts`, это единственное место, которое нужно
поменять при переходе на тайлсет из Tiled.

## Проверки

```bash
pnpm typecheck                              # все пакеты
pnpm check                                  # лок-файл + подпись Telegram + раскладка мира
pnpm --filter @tg-mmo/server smoke          # боты подключаются и бегают
BOTS=50 RUN_MS=30000 pnpm --filter @tg-mmo/server smoke   # нагрузочный прогон
```

Для `smoke` сервер должен быть запущен с `DEV_LOGIN=1`.

## Защита от читов

Клиенту не доверяется ничего: он присылает только намерение движения
(`dx`, `dy`, `dt`), а сервер сам считает позицию по общей функции коллизий.
Каждый пакет ограничен `MAX_INPUT_DT_MS`, а суммарное «симулированное время»
за реальную секунду — `INPUT_DT_BUDGET_PER_SEC`, что закрывает спидхак.
Кулдауны, мана, урон и опыт считаются только на сервере.

## Деплой

Один сервис плюс Postgres. Подробно — [`docs/deploy-railway.md`](docs/deploy-railway.md).

Команды берутся из `railway.json` в корне:

```
Build     pnpm install --frozen-lockfile && pnpm build
Start     pnpm start
Health    /api/health
```

Railway заводит сервис на каждый пакет воркспейса, так что после импорта
удали лишний `@tg-mmo/client` — сервер раздаёт клиент сам.

Переменные: `JWT_SECRET`, `BOT_TOKEN`, `WEBAPP_URL`, `DEV_LOGIN=0`,
`DATABASE_URL`. `PORT` подставляет хостинг. Адреса клиенту задавать не нужно —
он на том же домене, а миграции сервер применяет сам при старте.

## Что дальше

1. **AOI (area of interest)** — сейчас состояние комнаты рассылается целиком.
   На карте 2048×2048 со 100 игроками это ещё нормально, но перед ростом нужно
   фильтровать по `VIEW_RADIUS` (в Colyseus — `StateView` / `@filter`).
2. **Зоны как отдельные комнаты** и Redis-presence для нескольких игровых нод
   (тогда же понадобится разделить процесс — `SERVE_CLIENT=0`, `RUN_BOT=0`).
3. **Инвентарь и лут** — таблицы есть, дропа с монстров пока нет.
4. **Telegram Stars** — покупки внутри игры через Bot API (обязательны для цифровых товаров).
5. **Тайлсет и объекты карты** вместо процедурной земли.
6. **PvP**, гильдии, рейтинги на Redis ZSET.
